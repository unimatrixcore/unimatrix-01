# Poker OCR model tooling

The `dev_tools/training` tree preserves the current Poker repository's inference, training, export and qualification tools with their relative import layout. The collector's contract adapter and database source are retained for runtime schema and source-fingerprint compatibility. They do not start an application server.

The desktop inference entry point is `dev_tools/training/collector_inference.py`. It uses OpenCV, NumPy and ONNX Runtime with the existing frozen general/name model release. Paddle dependencies belong to the training/export tools. Model weights, Python environments, datasets and credentials stay outside source control.

Select the existing model interpreter and release with `OCR_MODEL_PYTHON`, `OCR_MODEL_RELEASE` and `OCR_MODEL_DEVICE`. A successful worker fixture test is not CUDA-placement or fresh physical OCR proof. Preserve the release's raw BGR preprocessing, dictionary/weight pins and contract identity when replacing this worker.

OCR Training freezes the selected collections into `$POKER_DATA_DIR/ocr-training/lab-runs/<version>` (the normal Poker XDG data directory supplies the default). Only matching review evidence admits crops. Exact decoded-pixel duplicates share one representative, preferring newer captures within the same evidence class; unresolved label conflicts are quarantined. Capture groups and inherited split assignments keep protected holdouts out of optimization. The data audit records inherited validation/test examples and constructed blank controls; unrelated baseline training crops are excluded. Player-name training is skipped when the selection has no eligible name targets.

Selected legacy crops can reuse the vetted historical audit only when category, decoded pixels, PNG hash, and current/original label match its recorded aliases. Historical corrections apply to the frozen training manifest, not the source database. This evidence remains `audited_baseline`; it does not create a current human review event or a new visual-verification claim. Current review conflicts and AI blockers still take precedence. Reserved validation/test crops are counted separately from rejected data.

Selecting collections checks GPU availability without preparing their data. Start creates one fresh snapshot: reading captures, validating labels and pixels, deduplicating, and reserving benchmark crops before model training. Eligibility counts come from that preparation; inherited baseline aliases and controls stay separate. Unsupported checkpoint characters are excluded with their original labels and reasons preserved.

The supervisor discovers the vetted recipes and checkpoints under `ocr-training/named-continuation`, the local training interpreter under `desktop-train-gpu`, and the benchmark interpreter under `desktop-gpu` or `runtime-venv`. `OCR_TRAINING_PYTHON` selects the supervisor interpreter. SSH uses the existing `unimatrix-01` host configuration and requires noninteractive key access, `rsync`, and its existing Paddle GPU environment. General OCR trains locally while player names train remotely. A lost SSH connection stops the remote training process group. Closing Poker Lab leaves its detached supervisor running; Stop requests cleanup before another run can start.

Each candidate retains its data audit, checkpoints, code and artifact hashes, export parity report, logs, and paired GPU benchmarks on frozen test crops. The comparison uses `OCR_MODEL_RELEASE` when set, otherwise the frozen release under `ocr-training/release-candidate`. Benchmark latency covers crop inference, not frame capture or the whole application. Completed candidates never replace the active models automatically.

Version numbers persist across restarts. Worker epoch, loss, step, and ETA come from training logs; absent measurements remain unknown. Epoch targets come from the frozen stage recipe before the first measurement. Initialization and checkpoint/tool transfers publish their current operation, and stage changes clear prior-stage measurements. Existing detached runs retain their frozen supervisor code. GPU readiness uses cached CUDA allocation probes rather than provider registration. Version comparisons retain their baseline hashes even when the active release changes.

Resume retains the version and frozen data, validates saved model/optimizer/epoch checkpoints, and reuses completed model jobs by hash. Each recovery keeps its prior run state and code snapshot under `attempts/`. Restored counters and best validation metrics must accompany the upstream model/optimizer loader; resetting either loses checkpoint-selection history. The behavior-gated tensor scalar compatibility policy preserves AMP overflow-step skipping and dynamic loss scaling on NumPy versions that reject Paddle's one-element-array conversion.

A smoke run with reduced training and test manifests verifies orchestration only. Judge candidate quality from its complete frozen test and stress reports; fixture lifecycle tests, dry-run admission, and CUDA allocation checks cannot establish improved accuracy. Runtime promotion additionally requires independent physical capture acceptance.
