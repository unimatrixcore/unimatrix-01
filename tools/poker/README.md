# Poker OCR model tooling

The `dev_tools/training` tree preserves the current Poker repository's inference, training, export and qualification tools with their relative import layout. The collector's contract adapter and database source are retained for runtime schema and source-fingerprint compatibility. They do not start an application server.

The desktop inference entry point is `dev_tools/training/collector_inference.py`. It uses OpenCV, NumPy and ONNX Runtime with the existing frozen general/name model release. Paddle dependencies belong to the training/export tools. Model weights, Python environments, datasets and credentials stay outside source control.

Select the existing model interpreter and release with `OCR_MODEL_PYTHON`, `OCR_MODEL_RELEASE` and `OCR_MODEL_DEVICE`. A successful worker fixture test is not CUDA-placement or fresh physical OCR proof. Preserve the release's raw BGR preprocessing, dictionary/weight pins and contract identity when replacing this worker.

OCR Training freezes the selected collections into `$POKER_DATA_DIR/ocr-training/lab-runs/<version>` (the normal Poker XDG data directory supplies the default). Matching review evidence or screenshot-bound synthetic annotations admit crops. Synthetic collections retain full 1920×1080 screenshots; preparation crops their `synthetic_regions` annotations and validates the corresponding `synthetic_ground_truth` evidence against the source pixels, labels, and rectangles. Synthetic evidence stays train-only and does not claim human visual verification. Exact decoded-pixel duplicates share one representative, preferring newer captures within the same evidence class; unresolved label conflicts are quarantined. Capture groups and inherited split assignments keep protected holdouts out of optimization. The data audit records inherited validation/test examples and constructed blank controls; unrelated baseline training crops are excluded. Player-name training is skipped when the selection has no eligible name targets.

Components with known partition roles retain their complete capture membership on one recorded anchor. Their shared component identity and known roles preserve the capture/session constraints without copying the same capture list onto every sample. If dictionary filtering removes that anchor, a surviving row keeps its capture and session edges. Unassigned components retain their existing fresh-session behavior. Export validates and materializes crop bytes one at a time within a consistent read-only database snapshot. Export and preparation stream manifests so large synthetic collections do not require whole serialized manifests in memory. Reservation reporting parses the inventory once into a compact index by collection; readiness scans stream full rows.

Split-pot aggregate regions with multiple amount panels retain their labels and capture membership as layout evidence. Recognition training uses the individual pot regions; single-panel and empty aggregate targets retain their existing admission checks.

Annotation preparation retains raw source rectangles for the training curriculum. Gameplay's live auto-cropper separately resolves visible panels and applies its source-derived rounded masks. Validate live panel detection independently when adding a renderer style or layout; source-bound labels alone do not establish that the live localizer accepts that scene.

Overlapping chip-column bet panels use their visible currency markers, source anchors and paint order to isolate each panel. Foreground pixels are removed from covered crops. Partial bets pass observed text runs to local OCR after removing ink clusters at uncertain cut boundaries. The original panel remains reference evidence; the result retains separate run predictions and open/closed boundary metadata, without promoting a numeric prefix to a complete amount. Unsupported source geometry and unresolved panel boundaries remain blocked.

Synthetic visible-run annotations use the same extractor as inference. Preparation reconstructs their pixels from the full screenshot and lossless coverage counts, verifies paired full-screen references and each retained source glyph, and projects only `recognition_target` into the training label. The full `source_label` stays in provenance. Both Paddle label writers reject substituting it for the verified observed transcript. A fully hidden target produces no recognition row; it is not a blank control. Visible runs use the selected candidate dictionary with the existing CTC loss and image normalization.

Selected renderer observations enter their training stages unchanged, separately from constructed glyph and blank controls. They receive no real-crop augmentation and cannot supply historical glyph-control parents. Curriculum preparation checks every source image sequentially and retains only the current real augmentation parent's decoded pixels.

New training candidates use the `punctuation73` profile in `ocr_dictionary.py`. Frozen `compact70` artifacts retain their original character IDs. Preparation requires matching dictionary, architecture and complete official tensor-mapping proof; export and inference reject reordered dictionaries and mismatched output heads. The new clean initialization selects its character columns from the untouched official checkpoint and leaves active releases unchanged. A verified source exclusion caused only by its older dictionary can be reassessed against the selected candidate profile; source eligibility and geometric exclusions remain recorded separately.

Selected legacy crops can reuse the vetted historical audit only when category, decoded pixels, PNG hash, and current/original label match its recorded aliases. Historical corrections apply to the frozen training manifest, not the source database. This evidence remains `audited_baseline`; it does not create a current human review event or a new visual-verification claim. Current review conflicts and AI blockers still take precedence. Reserved validation/test crops are counted separately from rejected data. Fixed glyph controls validate their parents against the full audited train-only partition, independently of collection selection; those parents do not become selected real training examples. Held-out, blocked, changed, or conflicted parents remain ineligible.

Selecting collections checks GPU availability without preparing their data. Start creates one fresh snapshot: reading captures, validating labels and pixels, deduplicating, and reserving benchmark crops before model training. Eligibility counts come from that preparation; inherited baseline aliases and controls stay separate. Unsupported checkpoint characters are excluded with their original labels and reasons preserved.

The supervisor discovers the vetted recipes and checkpoints under `ocr-training/named-continuation`, the local training interpreter under `desktop-train-gpu`, and the benchmark interpreter under `desktop-gpu` or `runtime-venv`. `OCR_TRAINING_PYTHON` selects the supervisor interpreter. SSH uses the existing `unimatrix-01` host configuration and requires noninteractive key access, `rsync`, and its existing Paddle GPU environment. General OCR trains locally while player names train remotely. A lost SSH connection stops the remote training process group. Closing Poker Lab leaves its detached supervisor running; Stop requests cleanup before another run can start.

Each candidate retains its data audit, checkpoints, code and artifact hashes, export parity report, logs, and paired GPU benchmarks on frozen test crops. The comparison uses `OCR_MODEL_RELEASE` when set, otherwise the frozen release under `ocr-training/release-candidate`. Benchmark latency covers crop inference, not frame capture or the whole application. Completed candidates never replace the active models automatically.

Version numbers persist across restarts. Worker epoch, loss, step, and ETA come from training logs; absent measurements remain unknown. Epoch targets come from the frozen stage recipe before the first measurement. Initialization and checkpoint/tool transfers publish their current operation, and stage changes clear prior-stage measurements. Existing detached runs retain their frozen supervisor code. GPU readiness uses cached CUDA allocation probes rather than provider registration. Version comparisons retain their baseline hashes even when the active release changes.

Resume retains the version and frozen data, validates saved model/optimizer/epoch checkpoints, and reuses completed model jobs by hash. Each recovery keeps its prior run state and code snapshot under `attempts/`. Restored counters and best validation metrics must accompany the upstream model/optimizer loader; resetting either loses checkpoint-selection history. The behavior-gated tensor scalar compatibility policy preserves AMP overflow-step skipping and dynamic loss scaling on NumPy versions that reject Paddle's one-element-array conversion.

Recovery requires the original persisted baseline pins. Incomplete saved checkpoints require a completed-save receipt covering the model, optimizer, and state files; damaged candidates are skipped when another verified save exists. Unreceipted legacy checkpoints are not adopted, and runs without original baseline pins require a new training version. Remote recovery fetches only stages last owned by the remote worker, preserving newer local Names checkpoints.

A smoke run with reduced training and test manifests verifies orchestration only. Judge candidate quality from its complete frozen test and stress reports; fixture lifecycle tests, dry-run admission, and CUDA allocation checks cannot establish improved accuracy. Runtime promotion additionally requires independent physical capture acceptance.
